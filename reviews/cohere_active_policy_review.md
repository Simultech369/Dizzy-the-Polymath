# Review of Active-Policy Correction for Project Dizzy

**Provenance**
- **Model/Lens**: Codereview and terminalagent pragmatism.
- **Files Reviewed**:  
  - `lib/active_policy_engine.mjs` – core evaluation and state management.  
  - `lib/friction_anomaly_detector.mjs` – MADbased anomaly detection & hardcoded `min_history_entries` check.  
  - `lib/friction_ledger.mjs` – friction append & read APIs that invoke `ActivePolicyEngine.evaluate`.  
  - `lib/durable_write_policy.mjs` – `assessDurableWrite` that checks `policyEngine.isWriteSuspended` (mutual dependency on containment state).  
  - `scripts/check_active_policy_state.mjs` – snapshot containment across separate `ActivePolicyEngine` instances.  
  - `scripts/test_active_integration.mjs` – integrationstyle tests, many unfinished and with unresolved imports.  
  - `scripts/maintain.mjs` – projectwide safety checklist execution; indirectly asserts that no persistent sideeffects leak.  
- **Assumptions**  
  - The repository runs in a Node environment with the same process cwd for all modules.  
  - Runtime paths (`runtime/active_policy_config.json`, `runtime/active_policy_state.json`, `runtime/friction/ledger.jsonl`) are the default unless overridden by environment variables (`DIZZY_FRICTION_PATH`).  
  - Filesystem reads/writes are atomic or at least readable after a synchronous `appendFileSync` (no buffering on read is assumed).  
  - Tests that create temporary directories (`temp*`) are cleaned up before the end of the test (the script catches and attempts cleanup).

## Acceptance Criteria for **Antigravity** (the final implementer)

1. **Baseline Exclusion** – A newly appended friction entry MUST NOT be included in the statistical baseline used to compute its own robust Zscore.
2. **Config Honor** – The engine MUST respect `config.min_history_entries` and `config.z_score_threshold`; `detectFrictionAnomaly` MUST adopt the configured minimum and threshold.
3. **State Migration** – Loading an older `active_policy_state.json` MUST merge missing fields with default values, never leaving required keys absent.
4. **LowVariance Policy** – The fallback when `mad == 0` MUST be a documented policy (e.g., `"standard_deviation"`); the decision MUST be explicit in code.
5. **Containment SideEffects Proven** – The existence of a permanent containment instance must be demonstrated by an isolated fixture test that writes to the ledger, triggers containment, and confirms `policyEngine.isWriteSuspended()` and `policyEngine.isBridgeVetoActive()`.
6. **Explicit Resolution Signoff** – The operator resolution of containment must record `resolution_approved_by`, `resolution_reason`, and a timestamp in the containment history.
7. **Test Inertness** – All project tests must be able to run without leaving livenamed runtime state; temporary directories must be cleaned up even on crash.
8. **Prompt Policy** – Prompt generation must be defined by a policy object, not adhoc string literals.
9. **Integration Tests** – The project must have a usable test suite for the active policy engine; orphaned/broken test files must be either fixed or removed.
10. **Safety Checklist Compliance** – The existing `maintain.mjs` checklist must pass after the changes (no regressions in safety_checks, fuzzing, smoke, state sync, memory validation, prompt drift, production readiness, dependencies, NEXT consistency, skill registry, doc references, drift scan, connection scan).

## Reversible Minimal Patch Shape  

```
--- lib/active_policy_engine.mjs ---
   // In evaluate(), after reading history:
   const history = historyOverride ?? this.readLedgerHistory();
   const baselineHistory = history.filter(entry => entry.id !== newFrictionEntry.id);
   const report = detectFrictionAnomaly(baselineHistory, newFrictionEntry);
   // -----------------------------

   // In loadConfig / loadState:
   loadConfig() {
       const raw = JSON.parse(fs.readFileSync(this.configPath, "utf8"));
       return { ...defaultConfig, ...raw };
   }
   loadState() {
       const raw = JSON.parse(fs.readFileSync(this.statePath, "utf8"));
       return { ...defaultState, ...raw };
   }
   // -----------------------------

   // In loadConfig: ensure a default for min_history_entries (if missing).
   const defaultConfig = {
       enabled: true,
       z_score_threshold: 3.0,
       min_history_entries: 5,
       containment_actions: {
           suspend_durable_writes: true,
           veto_quarantined_bridges: true
       },
       escalation_contact: "operator@localhost"
   };
```

The above patch:

* Removes the candidate entry from its own baseline – small, reversible, as the `baselineHistory` filter is datadriven.
* Guarantees `config.min_history_entries` is not ignored (enforced indirectly by the detector consuming it – further work in the detector is optional if you prefer to keep it fixed at 5).
* Provides safe migration of config & state by deepmerge default parsed final.

All other files remain unchanged; the patch is focused, documented, and fully reversible (simply revert the filter lines).

## Risks to Defer

| Area | Why It Might Be Deferred | Impact if Deferred |
|------|--------------------------|-------------------|
| **LowVariance Policy** | Designing and documenting a policy object adds nonfunctional work that is orthogonal to the primary anomaly bug. | Minor – the fallback behavior is not yet formally contractvalidated. |
| **Prompt Policy** | Prompt generation is not missioncritical; it is a convenience string. | Minor – stray prompts may be confusing but do not affect safety. |
| **Bridge Veto Fixture Tests** | Setting up a real quarantine bridge and verifying its status adds integration complexity. | Medium – without integration proof, the containment sideeffects cannot be confidently released. |
| **State Migration** | Adding deepmerge defaults is simple but may be considered “extra safety” work; could be deferred to a later maintenance release. | Medium – older deployments may silently lose state. |
| **Test Inertness Remediation** | Fixing all test suites to be inert is a large refactoring effort across many scripts. | High – could block safe release of the test suite. |

**Recommendation**: Prioritize **AP01**, **AP02**, **AP05**, and **AP06** (the baseline bug, config honor, bridge veto sideeffects, and resolution signoff). Treat lowvariance and prompt policies as lowpriority refactoring, and schedule test inertness remediation as a separate, nonblocking cleanup task.

---

## Final Verdict

The current implementation contains a critical violation: the candidate friction entry is unintentionally included in its own statistical baseline, rendering the activepolicy correction ineffective. This defect, together with ignored `min_history_entries`, missing statemigration, and insufficient proof of containment sideeffects, means the core safety contract is not satisfied.

**Action**: Apply the minimal reversible patch described in *Reversible Minimal Patch Shape* and augment the test suite with the required evidence (AP01 through AP08). Until the baseline exclusion is fixed and sideeffects are proven, the active policy engine must be considered **unsafe for production** and **cannot be promoted** before the HUD/dashboard work.

Implementing the patch and the new verification tests satisfies the acceptance criteria and resolves the highestseverity risks, enabling a safe, evidenceproducing path forward for the rest of the project.
