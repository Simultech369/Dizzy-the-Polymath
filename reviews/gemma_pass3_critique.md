## 1. Mathematical Vulnerabilities & NaN Propagation

### 1.1 SVG Sparkline Division-by-Zero
- **Target File**: [dashboard.js](file:///c:/Users/Josh/clawd/dashboard/dashboard.js#L1027-L1048) (Line 1027)
- **Vulnerability**: 
  In the `drawSparkline` function, the coordinate calculation maps the index of each value to an X coordinate:
  ```javascript
  const x = (idx / (values.length - 1)) * width;
  ```
  If `values` contains exactly **one element** (e.g., a single-node history array from an early scenario simulation run), then `values.length - 1` evaluates to `0`. 
  At index `0`, this results in `0 / 0`, yielding `NaN`. Consequently, the generated SVG points string will contain `NaN,y`, which is invalid geometry. This causes the browser to reject the path or throw rendering errors.
- **Exploit/Trigger**: Running a simulation with only 1 step or retrieving a single historical datapoint.
- **Remedy**: Insert an explicit guard to handle array lengths less than or equal to 1. If length is 1, return a flat line or a single centered circle.
  ```javascript
  if (values.length <= 1) {
    // Render flat line or empty sparkline placeholder
    return;
  }
  ```

### 1.2 MDS Pressure Calculation & Coordinate Clamping
- **Target File**: [dashboard.js](file:///c:/Users/Josh/clawd/dashboard/dashboard.js#L1083-L1100) (Line 1083)
- **Vulnerability**:
  The frontend `updateMDSPressure` function calculates the average friction weight:
  ```javascript
  const frictionMap = { low: 0.1, medium: 0.5, high: 0.9 };
  const totalWeight = nodes.reduce((sum, n) => sum + (frictionMap[n.friction] || 0.2), 0);
  const avgFriction = totalWeight / nodes.length;
  ```
  While this functions correctly for standard cases, it lacks integration safety with the backend coordinate projection. If the backend fails to validate incoming option friction values, a corrupted or non-standard friction key (e.g., `"chronic"`) will bypass validation.
- **Target File**: [options_projection.mjs](file:///c:/Users/Josh/clawd/lib/options_projection.mjs#L16-L98) (Line 37)
  In `projectCoordinatesRaw`, the weight lookup occurs as follows:
  ```javascript
  const frictionWeights = { low: 0.1, medium: 0.5, high: 0.9 };
  ...
  const fDist = Math.abs(frictionWeights[nodes[i].friction] - frictionWeights[nodes[j].friction]);
  ```
  If `nodes[i].friction` is set to any value outside the three standard keys (low, medium, high), `frictionWeights[nodes[i].friction]` returns `undefined`. 
  This causes `fDist` to compute as `NaN`, which propagates to the distance matrix `targetDistances` and forces the displacement solver to accumulate `NaN` coordinates. 
  Ultimately, coordinates `nodes[i].x` and `nodes[i].y` resolve to `NaN`, and the backend sends `left: "NaN%"` and `top: "NaN%"` to the client. The frontend dashboard then fails to render coordinates, leading to a silent UI breakdown.
- **Remedy**: Sanitize the friction field in the backend option mapper before processing the force-directed simulation.
  ```javascript
  const validFrictions = ["low", "medium", "high"];
  const friction = opt.friction || "low";
  node.friction = validFrictions.includes(friction) ? friction : "low";
  ```

## 2. Memory Footprint & Cache Eviction Safeguards

### 2.1 Cache Eviction Strategy Analysis
- **Target File**: [options_projection.mjs](file:///c:/Users/Josh/clawd/lib/options_projection.mjs#L100-L131) (Line 103)
- **Critique**:
  The cache implementation uses a global `Map` capped at `MAX_CACHE_SIZE = 100`. While the count of entries is bounded, this fails to prevent high memory usage under several conditions:
  1. **Object Reference Retention**: The cached array stores references to the original options objects (`node.opt`). If the caller passes options containing large embedded payloads (e.g., prompts, logs, or system graphs), these objects are pinned in memory and cannot be garbage collected until their cache key is evicted.
  2. **Cache Key Bloat**: The key is generated by joining option descriptions:
     ```javascript
     const optionHash = options.map(opt => `${opt.option_id}:${opt.description}:${opt.friction}`).sort().join("||");
     ```
     For option lists with lengthy descriptions or numerous items, the key string itself can consume hundreds of kilobytes, compounding memory consumption.
  3. **Stale Metadata/Leakage**: The cache key ONLY includes `option_id`, `description`, and `friction`. If option objects have identical descriptions and friction but contain differing metadata (such as active votes, weights, or dynamic session data), a cache hit will return the *stale metadata* from the first cached execution, leading to data drift.
  4. **Solver Denial of Service**: The spring solver running inside `projectCoordinatesRaw` has a time complexity of $O(\text{iterations} \cdot n^2)$ where $n$ is the number of options. Since there is no limit on `options.length` at the API boundary, an attacker or oversized configuration could feed 500+ options, causing the solver to run millions of loops synchronously, freezing the Node.js event loop and causing a denial of service.

- **Remedy**:
  - Deserialize the options objects or only cache coordinate mappings (`left`/`top`) mapped by a cryptographic hash of the options, rather than holding references to full user-provided objects.
  - Implement a hard limit on option list sizes (e.g. maximum 50 options) to block execution of heavy solver runs.
  - Include all option properties in the hash calculation to avoid returning stale metadata.

## 3. Asynchronous Error Handling & Resource Leaks

### 3.1 Silent Temporary Directory Leaks
- **Target File**: [scenario_simulator.mjs](file:///c:/Users/Josh/clawd/lib/scenario_simulator.mjs#L136-L159) (Line 136)
- **Vulnerability**:
  In `runIsolatedSimulation`, a temporary directory is created inside `os.tmpdir()`:
  ```javascript
  const tempDir = await fs.promises.mkdtemp(path.join(os.tmpdir(), "dizzy-sim-"));
  ```
  The cleanup takes place inside the `finally` block:
  ```javascript
  } finally {
    try {
      await fs.promises.rm(tempDir, { recursive: true, force: true });
    } catch {
      // ignore cleanup errors
    }
  }
  ```
  If `fs.promises.rm` fails (which frequently happens on Windows due to file locks by antivirus scans, indexing services, or active file handles), the exception is swallowed and silently discarded. 
  No logging, alert, or retry mechanism exists. The directory and its nested `sim_checkpoint.json` remain permanently on disk. Under automated, high-frequency execution, this creates a slow filesystem leak that will eventually consume available inodes or disk space.
- **Remedy**:
  Instead of silently swallowing cleanup exceptions, register a warning via system logs or a diagnostic health status, and implement a retry queue or schedule a background task to retry directory cleanups that failed.

## 4. Concurrency & Performance Analysis

### 4.1 Node Event-Loop Blockage
- **Target File**: [friction_ledger.mjs](file:///c:/Users/Josh/clawd/lib/friction_ledger.mjs#L176-L195) (Line 184)
  `readFrictionEntries` uses `fs.promises.readFile(filePath, "utf8")` to read the entire ledger file. Once read, it splits the entire file contents:
  ```javascript
  const lines = content.split(/\r?\n/).filter(Boolean).slice(-maxRows);
  ```
  If the ledger file grows large over time, reading megabytes of string data and executing `split` on the main thread blocks the event loop. The API becomes unresponsive during execution.
- **Target File**: [dashboard.mjs](file:///c:/Users/Josh/clawd/lib/dashboard.mjs#L292) (Line 292)
  Endpoints like `/api/operator/consensus-map` load consensus data by calling `getConsensusState()`, which in turn triggers `fs.readFileSync` synchronously. Running synchronous I/O operations inside route handlers blocks the Node.js thread for all incoming network requests.

### 4.2 Race Conditions in Bridge Merging
- **Target File**: [dashboard.mjs](file:///c:/Users/Josh/clawd/lib/dashboard.mjs#L355-L370) (Line 355)
  The quarantine bridge acceptance handler uses a non-atomic read-modify-write pattern:
  ```javascript
  const acceptedContent = await fs.promises.readFile(acceptedBridgesPath, "utf8");
  ...
  await fs.promises.writeFile(acceptedBridgesPath, JSON.stringify(accepted, null, 2), "utf8");
  ```
  If two operators or automated tasks approve separate quarantine memory bridges concurrently, the async read operations will execute in parallel, and whichever request writes last will overwrite the other's entry. This causes permanent data loss in `accepted_bridges.json`.
- **Remedy**:
  - Replace synchronous file operations in route handlers with their `fs.promises` counterparts.
  - Implement a file-level write lock or a queue for updates to `accepted_bridges.json` to prevent concurrent write collisions.
  - Replace full-file ledger reading and splitting with line-by-line streaming or reverse-byte reading to only fetch the tail lines.
